### 2.1 矩阵里那三条"根本没有的世界任务"是什么

`MatrixRows` 现在列 21 行，其中三条零客户端凭据：

| questID | 名字 | 分组 | 到期 | 凭据 |
|---|---|---|---|---|
| 82157 | 特别任务：巨兽崛起 | -1（未知地图） | 10-29 06:59 `expiresSrc=下次周重置` | 无池/无日志/无注册/`lastMoney=nil`/无地图 |
| 86174 | 特别任务：风暴在即 | -1 | 同上 | 同上 |
| 96718 | 奈格塔尔虚空决战（英雄） | -1 | 同上 | 同上 —— **本行判定已由 §五"修订一"作废**：`db.chars` 里 14 个号本轮答过 `done` |

它们靠**唯一一道空转凭据**活着：`Ledger.lua:1683` 的 `kwHit = GQL.Config.KeywordMatch(name)` —— 只要账本里某条记录的**名字**撞上了
他配的关键词（"特别任务"/"虚空决战"），`Ledger.lua:1702-1705` 的五道准入门就放行；再靠 `Ledger.lua:1762` 的
`row.watched = kwHit or …` 跳过"本资料片地图"过滤，最后落到"未知地图"分组。到期时刻是 `L.SetCycleExpiry`
（`Ledger.lua:828-843`）给的下次周重置尾巴，所以名字还带个看起来真的倒计时。

**这就是"扫描导致的垃圾数据"的机制**：旧版补扫遍历整棵地图树（`Sync.lua:994` 注释记着，最多 800 张图，他当时明确否决：
"应该不需要全图扫描吧，我觉得只需要扫描用户添加的地图就好了"），扫到名字撞关键词的老资料片任务就建了账本行。

来源不可复原的两条实测：这三条记录里**没有任何"谁建的"戳**（`regKey`/`kwLogAdded` 都空，只有 `currentSig=-1` 和一条 observation），
`db.logs` 只留最后 200 行（`Config.lua:29` `MAX_LOGS=200`），建行的那条日志早被冲掉了。所以"到底是哪一次扫进来的"只能承认不知道。

### 2.3 「添加」按钮点不动，回车有效

`Panel.addBtn` 在 `Options.lua:496-511`，`OnClick` 与 `kwEdit` 的 `OnEnterPressed`（`:511` 走 `Panel.addBtn:Click()`）是**同一个函数体**——
所以处理逻辑没问题，是**点不到**。几何实测（数值都来自 `Options.lua:413-474` 同一套常量，窗口 640×420）：

- `kwEdit`：`BOTTOMLEFT (12,40)`，240×24 → x **12..252**，y 40..64
- `addBtn`：`LEFT kwEdit.RIGHT +6`，56×22 → x **258..314**，y 41..63（"添加"两字在 x≈286 正中）
- `Panel.scrollR`：`TOPLEFT (276,-56)` + `BOTTOMRIGHT (-12, **12**)` → x **276..628**，y 12..364

右栏视口的矩形把页脚那一条也占了：`addBtn` 右边 38px（含按钮中心）落在 `scrollR` 里面。`scrollR` 是 `f` 的子帧、
`EnableMouse(true)`（`:475`），它自己那一层在 `addBtn` 之上（子树层级比浅一层高），所以点在按钮文字上就是右栏吃掉。
对照组：`huntBtn`（"补扫跟踪地图"）x 12..172、y 12..34，**两只视口都不碰它**（`scrollL` 底边让到 `FOOT_H=74`，见 `:461`），
而他实测补扫是可点的——这正好是本窗口里两只按钮唯一的几何差别。

`FOOT_H = 74`（`:414`）当初只给了左栏（`:461` 用 `BOTTOMLEFT …, FOOT_H`），右栏漏了，注释 `:410-412` 写的"左栏底部让给两排固定控件"
其实就是没覆盖右栏这一句。

### 2.5 第 4 问的答案（写进文档，别只留在对话里）

特别任务**不在世界任务板上**，本轮实测过的三条来源都对它答不出：

1. `Sync.HuntKeywordMaps`（`Sync.lua:1003-1130`）现在只问**跟踪清单**里的图（他否决全图扫描后改的），
   问图走 `Api.MapQuestRows`（`Api.lua:1009`）= `C_TaskQuest.GetQuestsOnMap` → `C_QuestLog.GetQuestsOnMap` 两条板面清单，
   特别任务天生不在里面。他截图那句 "12 张图没有命中" 就是这条路的正常回报（`Sync.lua:1124`）。
2. 地图事件 pin：`Sync.lua:659-677` 只认 **pin 自己挂了 questID** 的事件；答不出 ID 的 pin 一行都不注册（拿事件名猜 ID 会把
   别的任务的完成状态冒充成它的）。他那句聊天尾巴"…只在地图事件 pin 里，客户端没给它任务号"就是这一支——
   **永歌森林那条真特别任务在客户端是"只有名字没有号"的 pin，补扫结构上就碰不到它**（不是扫描方法换了才漏，是它从来没在板面清单里过）。
3. 悬赏接口 `Api.BountyQuestIDs`（`Api.lua:1069`，`C_QuestLog.GetBountiesForMapID`）：12.1.5 实测每张图回同一批，
   被 `Api.MapQuestIndex` 的跨图自检否掉（`Api.lua:1063-1067` 原注），不能当凭据。

能成行的唯一路子已经存在并且没坏：**接上它** —— 任务日志那一路（`Sync.lua:218-243`）会把"名字命中关键词 + 在日志里"的任务
用 `AddQuest(..., "questlog")` 收进来并写 `kwLogAdded`，之后每轮按 CD 尾巴续期。所以给他的答复是：
**站到永歌森林接了那条特别任务，矩阵下一轮自动有它一行；不接就扫不到，这不是本轮能靠改扫描绕过去的事。**

顺带一条取证缺口（本轮补）：`Sync.lua:1124` 那句"命中 0 条 + pinNote 说明"只 `print` 到聊天，**没写进 `db.logs`**
（日志只留那句统计，`:1084-1085`），聊天滚过去就读不到了。
