# GQL 批量"本轮不做"（整行手势）+ 竖排角色名放开 设计

**Goal:** 在矩阵里右键**任务名那一格**，一条手势把这一行上所有还没做的角色一次标成"本轮不做"
（现在只能一个一个格子点），并给这一下加确认提醒。顺带把竖排左窗格被砍成 4 字的角色名放开。

**用户诉求原话**（2026-11-10 逐条问答定稿）：
「整个任务所有角色本轮不做，目前右键点击单元格，标记 X 表示该角色本轮不做，我想，在任务名所在的
单元格 右键，表示本轮所有角色都不做，但是要有个确认提醒。」
「先做理解 1 的版本，撤销是批量把不做的标记去掉，这样符合常规思维吧。因为我们目前只能一个一个的点。」
「角色竖排的时候名字长度不要有限制了……角色名字最多 7 个字，所以不用管，120 够了。」

## 已确认的六条口径

1. **落法 = 理解 1**：批量手势只往格子上写现成的 `skip`，**不新增任何记录、不新增存档字段**。
   任务这一行**留在矩阵里**（不下矩阵）；"整行下矩阵"那档本轮不做。
2. **✓ 不动**：已完成（含家族行"全族取最强"算出来的 done）的格子一律跳过不写 —— 与格子右键
   现有的"已完成不许被 × 盖掉"同一条口径（[Matrix.lua:277-294](file:///D:/Repos/wow/GoldQuestLedger/Matrix.lua#L277)）。
3. **撤 = 清这一行上所有的 ×**，包含以前单独给某个号点的那枚。不做"只清批量点上的那几个号"，
   所以不留"哪枚是批量来的"这种第二状态。
4. **记和撤都弹确认框**，用暴雪标准居中模态框（`StaticPopup`）；取消、ESC、点外面都一个字不写。
5. **两个模式都要有入口**：横排=任务名列整行热区，竖排=表头任务名那格。
6. **竖排左窗格角色名去掉 4 字截断**；横排列头那把 4 字刀本轮不动。

## 一、手势的判据（记 / 撤 / 无事可做）

按任务号取当前这一行的每号显示状态，分三类：

| 当前显示 | 记这一次 | 撤这一次 |
| --- | --- | --- |
| `done` | 不动 | 不动 |
| `skip` | 不动（**不重写**，免得刷新时间戳污染日志） | 清掉（`SetManual(...,"open")`） |
| 其余（空、`?`、`progress`、`ended`） | 写 `skip` | 不动 |

方向判定只有一条：**存在"既非 done 又非 skip"的格子 → 这一枪是"记"；否则 → 是"撤"。**
只有两种形状是"无事可做"→ **不弹框、不写账**，日志一行说明：整行本来就已经全 ✓（没有可撤的），
以及一个号都没有（矩阵空态，"还没有角色数据"那一屏）。
注意"整行全空"**不是**无事可做 —— 全空 = 全是可写的 = 走"记"。

`k` 算不出（新号首次上线那档，`L.InstanceKey` 回 nil）→ **不弹框、整批一个字不写**，走 fail-closed，
日志一行。不许"先按猜的亮 ×，回头再撤"。
**这一条比格子右键严格**（格子那一档 [Matrix.lua:288](file:///D:/Repos/wow/GoldQuestLedger/Matrix.lua#L288)
照写不误，只是读侧比不上键所以画不出来），本轮是有意收紧：一枪写十几格，把十几笔永远画不出来的
记录留在存档里不值当。实施**不许**为了"两处一致"把它对齐回格子那一档。

## 二、确认框

- 新增一条 `StaticPopupDialogs` 项（插件里目前**一个确认框都没有**，这是第一处），两个方向复用
  同一条目、只换文案与按钮回调；`data` 里只带 `questID` 与方向，不带旧状态表。
- 文案四行，全部取自这一行已经算好的读数，不为文案再问接口：
  - 任务名；
  - 地图 + 本轮到几点（`row.groupMapID` 的现成名 + `row.remaining` 折算的到期，`remaining` 为
    nil 时这一档整段不写，宁缺不编）；
  - 影响面 —— 记："14 个号：9 格记不做，4 格已完成保持 ✓，1 格已是 × 不动"；
    撤："清掉这一行上 13 枚 ×，含你以前单独点的"；
  - 按钮：确认 / 取消。
- **点确认时重新解析目标**（弹窗停在屏上期间可能 `/reload`、换轮、这一行消失）：`data` 里带
  `questID` + 那一刻算出的实例编号 `k` + 已定的方向；确认时按 `questID` 重新取这一行的每号状态，
  **执行弹窗那一刻已经定下的方向**，不搞"看见方向翻了就自己改主意"。
  - 行取不到 → 什么也不写，日志一行"这行已不在矩阵，未改动"；
  - **当前 `k` 与那一刻的 `k` 不同（确认期间换了实例）→ 整批不写**，日志一行"本轮已换，未改动"。
    这一条是必须的：不卡它就会把玩家对**上一条**实例的意向，静悄悄盖到刚刷新的新实例上；
  - 行还在、`k` 也一样，但该方向此刻一格都动不了（比如那几个号在确认期间全做完了）→ 同样不写，
    日志一行说明。
- **不许叠弹窗**：同一条目已在屏上时再右键直接忽略这一枪，日志一行，不重开也不改文案。
- 层级坑：矩阵打开那一下会临时占 `DIALOG`
  （[Matrix.lua:1513-1520](file:///D:/Repos/wow/GoldQuestLedger/Matrix.lua#L1513)），跨层比层号无效，
  同层才比 —— 弹之前沿用现成的 [`RaiseAboveMatrix`](file:///D:/Repos/wow/GoldQuestLedger/Options.lua#L888)
  那一招：先让矩阵退回 `MEDIUM` 再弹。
- ESC 归属要**实测确认**（矩阵自己挂了 ESC 关闭，[Matrix.lua:1609](file:///D:/Repos/wow/GoldQuestLedger/Matrix.lua#L1609)）：
  期望是 ESC 先取消确认框、不顺手关掉矩阵。这条不许当已知，写探针用例进真档清单。

## 六、测试（离线替身，`tests/run_gql_tests.py`）

新增用例钉住：

1. 批量记只碰"非 done 非 skip"的格子；`done` 保持 ✓；已是 `skip` 的不重写（比 `t` 不变）。
2. 批量撤清掉这一行上**所有** `skip`，含事先单独点的那枚；`done` 记录不受影响。
3. 方向判定：混合行（有 · 有 ×）→ 这一枪是"记"；记完再点 → 是"撤"。
4. 整行全 done → 不弹框、不写账、日志一行。
5. `k` 算不出（未定身份）→ 不弹框、整批不写，界面上不许出现亮着的 ×，存档里不许多出隐形记录。
6. 家族行：全族已算成 done 的格子不被批量写；家族里没做的格子正常写。
7. 确认框：取消/ESC/点外面都不写；确认后写入的数量与文案报的数字一致。
8. 弹窗期间换轮（推时钟过 `k` 的桶）→ 点确认**整批不写**、日志说明"本轮已换"；旧桶的格子也不许被动过。
9. 同一弹窗已在屏上时再右键 → 忽略、不叠。
10. 竖排表头那格走同一入口，结果与横排一致；顺带断言表头热区仍可悬停、滚轮仍可透传。
11. 点击路径**零 `Api.*` 调用**（替身计数断言，与既有纪律同一坑位）。
12. 竖排左窗格角色名：7 字全名完整画出、不截；过期那档是"全名+过期"；横排列头逐字不变。

静态手段定不死、只能装好后按一次的只有两条（都是界面层级/事件顺序，不是逻辑）：
① 确认框要出现在矩阵前面，不被压在后面看不见；② ESC 先关确认框、不顺手把矩阵一起关掉。
正常用一次批量就同时看到这两条的结果，不用另外跑图或开别的界面。

- 横排列头角色名放开。
- 把批量入口挂进「关键词 · 屏蔽管理」窗口，或让它管理永久 `ignored`。
- 新增存档字段、schema 迁移、任何轮询或补读。
