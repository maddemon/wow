# GoldQuestLedger 设计（多角色世界任务金币记录）

日期：2026-10-21
状态：已与用户逐节确认，待实现
插件目录：`GoldQuestLedger/`（与 `AHSnipe/` 并列，独立 .toc、独立 SavedVariables）

## 1. 要解决的问题

用户有多个角色，靠记忆无法回答"这个 CD 哪个角色还欠几个金币任务、各刷了多少钱"。市面上的金币任务插件要么只判定金币任务、要么只有单角色进度，缺少"全角色 × 全任务"的账本视图。

目标：任意角色登录后，能看到所有角色当前 CD 的世界任务完成情况与金币收益合计。

## 2. 已确认的口径

| 议题 | 决定 | 理由 |
|---|---|---|
| 金币任务判定 | 自动判定为主 + 手动锁定兜底 | 同一任务在狩猎/普通模式下金币属性可能不同 |
| 记录粒度 | 任务级（不分模式建列） | 先做简单版；模式差异放 tooltip 展示 |
| 录入方式 | 登录自动同步 + 地图气泡点击补录 | 手动全录入与"容易忘记"这个痛点冲突 |
| 覆盖范围 | 仅当前资料片开放的世界任务 | 列表短、改版自然淘汰 |
| 查看 UI | 任务 × 角色矩阵窗口 | 一眼看出哪个角色还欠几个 |
| 统计周期 | 按周 CD（国服周四） | 用户要求按周统计 |
| 金币合计 | 底部每角色本周金币总额 | 用户要求 |
| 宝箱类奖励 | 记"大概"即可 | 用户明确接受近似值 |
| 补录交互 | 必须点击，禁止输入任务名/命令 | 用户否决斜杠命令补录 |

## 3. 核心约束（API 硬限制，不是缺陷）

- 其它角色的任务状态**只有那个角色上线时才读得到**。每个角色列是"该角色最后一次登录时的快照"，UI 必须显示最后同步时间，过期列变灰。
- 12 小时刷新区（虚影风暴、屠戮者高地）的任务**不按周期推算**：刷新时池子里可能没有它，有也未必给金币。唯一真相是登录时抓到的世界任务池。
- 12.x（Interface 120105，与 AHSnipe 同版本）的世界任务、奖励查询、完成状态相关接口形态**未经实测**。实现第一步是探测，不按记忆写 API 调用（沿用 `feedback-addon-debugging` 约定：候选接口逐个 `pcall`，结果写日志窗口，由用户在游戏内回传文本）。

## 4. 金币数额为什么不用查询接口

数额一律用**交任务时实测的钱变化**：交任务前后各取一次 `GetMoney()`，事件后 15 秒窗口内的净增量归给该任务。任务直接给的金币和随后立刻开宝箱给的金币一次全收进来，不需要区分奖励类型，也不需要猜 12.x 的奖励查询接口。

误记风险：窗口内另有拍卖行到账或交易收款会串进来。缓解：只在交任务事件后才开窗；窗口内若打开过邮箱/拍卖行则放弃本次测量，记 `g = nil`（UI 显示 `?`），而不是记一个可疑数字。手动可用步进按钮校正。

"是否金币任务"这个标记仍需在**没做过**时就能显示（否则看不到还欠哪些），由第 6 节的池快照 + 奖励签名自动判定。

## 5. 周 CD 锚点

不写死星期几。用服务端返回的下一次周刷新时间戳反推本 CD 起点 = `nextReset − 7 天`。库里存 `cycleAnchor`（上次算出的本 CD 起点），登录后重算，值变化即进入新 CD：本周统计自动归零显示，历史 CD 数据保留可翻。

锚点与交任务时间戳必须落在同一个时钟域，否则跨一次开机就没法比：`GetTime()` 是"本次开机后秒数"，重启归零。所以入库时间戳用墙上时钟（纪元秒），并把实际使用的域记在 `clockDomain`；`/gql probe` 会并排打出 `GetQuestResetTime` / `GetTime` / 墙上时钟三个值，用实测结果确定 `GetQuestResetTime` 到底属于哪个域。拿不到可信墙上时钟时退化为会话域，此时周统计只在本次开机内可靠，必须如实标注而不是假装算得准。

## 6. 数据来源与优先级

按可信度排序，三条并存：

**A. 交任务事件实时记账（主来源）**
监听交任务完成事件，命中即在当前角色写一条 turn-in 日志并按第 4 节记 `g`。这是插件亲眼看到的，最可信。附带自学习：实测 `g > 0` 就把该任务该签名标为金币任务。

**B. 登录池快照 diff（回填与校准）**
每次登录（及世界任务更新事件去抖 1–2 秒后）抓当前角色的世界任务池，与账本 diff：

- **新出现**（本次池里有、账本里该 questID 当前处于 `goneSince` 状态或从未记录）→ 入表、跑金币判定、计入"本轮应做"，并把上一轮的已交状态归档（本轮重新计为待做）。
- **消失**（账本有、池里没有）→ 写 `goneSince = now`，移出"本轮应做"；已交记录与历史不动。
- **仍在** → 刷新 `lastSeen`，并比对**奖励签名**（金币数额 + 奖励物品 ID 列表的序列化）。签名变化 → 判定为模式差异或奖励改版，重新判金币并写日志。

"本轮"的定义就是**连续存在于两次池快照之间**，不设时间阈值：任务消失后再出现就算新一轮，无论隔 12 小时还是 4 天。这样高频区与周常区共用同一套逻辑，也不需要插件知道任何刷新周期。

高频区（12 小时级）的行加"高频"标记；本轮已结束的任务显示"本轮已结束"而非"待做"，避免误判成漏做。

**C. 手动覆盖**
地图气泡头像点击、矩阵整列/整行一键、tooltip 步进按钮。手动写入的标 `source = manual` + `goldLock`，后续自动同步不再覆盖。
"不再覆盖"只到**这一条实例结束**：补录也分轮次（第二十六轮，§26），换轮后那一格回到自动判定，想要就得再点一次。
**这一层只管格子的完成状态，不管一行该不该出现在矩阵里**：第二十七轮（§27）起，"添加任务"点一下只撤销
永久屏蔽（`ignored`），不再有 `manualAdded` 那道绕门槛的准入门——一条任务上不上板只由客户端证据
（在不在板上 / 本轮金币 / 本轮有人交过 / 客户端答过它的图）和玩家配置（金币门槛 / 注册周常）决定。
第三十二轮（§32）把**关键词命中从"客户端证据"里摘出去**：名字撞关键词只让它免掉金币门槛，
不再单独够格上板——老资料片那些"名字像、任务早没了"的残留记录从此进不来。

## 7. 数据模型

单一 account-wide SavedVariables `GQLDB`（顶层带 `schema` 版本号）：

```
GQLDB = {
  schema = 1,
  cycleAnchor = <本 CD 起点时间戳>,
  clockDomain = "epoch" | "uptime",   -- 时间戳存在哪个时钟域，见第 5 节

  quests[questID] = {
    name, mapID,
    goldLock = nil | true,          -- 手动锁定，屏蔽自动判定
    ignored = nil | true,           -- 玩家在"关键词 · 屏蔽管理"窗口点"忽略" = **永久**屏蔽
                                    --  （只有同一颗按钮点"取消忽略"才撤；矩阵不给屏蔽入口，2026-10-27 起右键
                                    --   不屏蔽任何东西；记录与金币账照留，Prune 也不按时丢它）
    highFreq = nil | true,          -- 由观测频率得出
    observations[rewardSig] = {
      gold = true|false,            -- 该签名是否金币任务
      money = <金币数额>,
      items = { itemID, ... },
      firstSeen, lastSeen, goneSince,
    },
  },

  chars["角色名-服务器"] = { class, level, lastSync },

  -- 追加日志，非"每任务一条"；按 CD 保留最近 8 条
  turnins[角色][questID] = { { t, g, sig, cycle }, ... },

  manual[角色][questID] = { state = "done"|"progress", t, g },  -- 手动覆盖，本轮内优先于快照（换轮作废，见 §6-C）
}
```

每角色"本周完成数"与"本周金币总额"从 `turnins` + `manual` + `cycle` 现算，不单独存，避免两处账对不上。

旧假设已废弃：`quests[questID].gold` 单一布尔、`turnins` 每角色每任务仅一条、靠 cadence 推算 `nextDue`。

## 8. UI

### 8.1 矩阵主窗口（`/gql` 开合，可拖动可缩放）

- 行 = 金币任务，按地图分组可折叠；行内容：图标 + 任务名 + 本轮可得金币（如 `~250G`）+ 高频标记。
- 列 = 角色；列头显示职业色角色名 + 本周完成数 `8/14`，副行显示最后同步时间，超 7 天未同步变灰。
- 单元格状态：`✓ 已交`（tooltip 给实际到账金币与时间）/ `● 已接未交` / `· 待做` / `⊘ 本轮已结束` / `? 未知`（API 取不到该态）。
- 底部合计行：每列该角色本周金币总额（含宝箱实测值），末格全账号本周合计。
- 顶部筛选：`全部 / 只看未完成 / 只看金币任务`，默认"只看金币任务 + 未完成优先"。
- 底部固定一个可折叠的**"未判定"分组**：奖励信息拿不到、且尚未做过的任务在这里（见第 12 节退化），做过一次即自动升入正式分组。

### 8.2 地图气泡补录（日常主路径）

- 在世界任务气泡上叠一排小角色头像；自己已做的打勾变灰。
- 点某头像 = 切换该角色该任务状态；点自己头像 = 记一笔。API 只能自动判定当前角色，他人状态来自账本、可能过期，故手动点击写入 `manual`，不被登录同步覆盖（只算这一条实例，换轮作废；换轮后那一格仍要能点掉自己点过的补录）。

### 8.3 手动批量与撤销（矩阵内）

- 点列头把角色加入"当前目标组"（可多选，再点取消）；未选任何列时格子只读，防误改。
- 编辑模式为显式开关，默认关；开启后 5 分钟无操作自动退回只读。
- 列头菜单：`本列全部标已交` / `本列全部清空`；行尾按钮：`本行给目标组全部标已交`；一个`撤销`按钮，回退最近 20 步手动操作（自动同步不入撤销栈）。
- 金币数额调整：tooltip 内 `−100 −10 +10 +100` 步进按钮 + `清除实测值`；无输入框。手动调过的数字带角标。

### 8.4 Tooltip

任务完整奖励（金币数额、物品图标、声望）、剩余时间（取池数据/区域倒计时，接口缺失则省略该行）、每角色状态、最近一次实际到账金币。同任务多签名时分模式列出，例："普通模式 250G / 狩猎模式 无金币"。

## 9. 模块划分

零依赖纯 Lua，复制 `GoldQuestLedger/` 到 `_retail_/Interface/AddOns/` 即可用（与 AHSnipe 一致）。

以下 11 个文件就是 `GoldQuestLedger.toc` 的加载顺序，一个不多一个不少（照实列，
别照本节去找不存在的代码：早期设想的 `Detect.lua` 摊进了 `Api.lua`（候选接口与降级）
和 `Ledger.lua`（判据），`MapOverlay.lua` 与 `Tooltip.lua` 从未独立成文件——地图上的
加任务在 `Track.lua`，悬停信息只有 `Matrix.lua` 一处 `GameTooltip`，§8.2 的气泡头像层
至今没做；`Commands.lua` 也没有，命令散在各文件自己 `GQL.RegisterCommand`）。

- `Core.lua`：入口——命名空间、`/gql` 子命令注册表（`config`/`dump`/`quest`/`log`/
  `matrix`/`probe`/`sync` 共 7 条，只有 `config` 在这里注册）、`ADDON_LOADED` 与
  `PLAYER_ENTERING_WORLD` 分发。不碰账本字段，也没有"一条 `/gql` 开合矩阵"这种命令。
- `Config.lua`：存档建库（`GQLDB`）、周 CD 锚点与时钟域口径、schema 档位与一次性升级
  （`Migrate` + `MIGRATIONS`）、金币与剩余时间格式化、诊断日志环、跟踪地图/关键词/
  金币门槛/登录同步这些可配项。不读世界任务数据接口——周重置倒计时也是问 `Api` 的。
  金币门槛的**界面入口** 2026-10-27 从设置面板撤下（用户口径四"暂时不能配置"）：
  `db.config.minGold` 仍是唯一真源，`MinMatrixMoney`/`GetMinGold`/`SetMinGold` 三个函数
  与矩阵那一道门槛一个都没动，只是暂时只能改存档。
  登录同步的**界面开关**同轮一起撤下（用户口径"默认就抓取 不用设置"）：`SyncOnLogin`/
  `SetSyncOnLogin` 与 `Sync.OnWorldEnter` 里 `loginPending` 那一句读档照旧，想关只能改存档
  `["syncOnLogin"] = false`——这颗开关不是白造的（用户 2026-10-24 实测过后台抓池会卡）。
- `Ledger.lua`：纯数据层（池 diff、轮次身份、状态与金币判据、周统计、
  `MatrixRows`/`MatrixColumns` 矩阵视图、体积清理）。不碰任何 WoW 接口，时间戳一律由
  调用方传入，因此可在 lupa 里离线跑。**没有撤销栈**：矩阵里的"移除"写 `ignored = true`
  （`L.RemoveQuest` = **永久屏蔽**，换 CD、换轮都不作废，只有玩家在"添加任务"打开的
  「关键词 · 屏蔽管理」窗口里点"取消忽略"才撤——
  用户 2026-10-27 的原话："我这个意图其实是想永久屏蔽的"），
  而"添加任务"那一路**不写任何上板凭据**（`L.AddQuest` 只清 `ignored` + 把记录建出来/刷新一次）：
  上一版那个 `manualAdded` 字段整体下线，矩阵准入门剩五道（关键词从日志收的 / 命中关键词 / 注册周常 /
  本轮有人交过 / 金币≥门槛）+ 一道永久否决；老存档里两份历史标记由升级档 v4/v5 一次性清掉。
  这五道第三十四轮抽成唯一真源 `Ledger.RowAdmitted`（`MatrixRows` 与 `/gql quest` 读同一条，门槛金额仍由
  `MatrixRows` 在循环外读一次传入，不许每条每帧问 `Config`）——诊断侧再拼一套的话，准入口径一改报告就说瞎话。
  其中"本轮有人交过"这一道从**第三十五轮**起不再无条件成立：判据是 `Ledger.TurnInAdmits(on, gain, noGold)`
  （唯一真源，矩阵与 `/gql quest` 都问它，另有静态守卫钉"这串只许出现一处"），只有
  **接（本轮奖励读到的金额 = 0）** 和 **交（本轮那几笔实际到手，每笔都是数字 0）** 两处客户端都答了 0 金币
  才不放行；任何一处答不出（金额 nil / 到手 nil / 任一笔 >0）照旧放行 —— 松露大乱斗那种
  "做了金币任务却读不到钱"（12.1.5：962 金只有悬停现问读得出）正是要保的样本。
  到手金额与"本轮交过"从同一次 `db.turnins` 遍历里聚出来（`Ledger.TurnInCred` 回 `on`/`gain` 两份表，
  `TurnedInThisRound` 只是 `.on` 的薄壳，返回形状没变）。"接"这一头认**本轮那个数**而不是 `obs.gold` 那面旗：
  `GoldVerdict` 从此在 `money == 0` 时答 false（搬来的 0 也算本轮答过，延续第 34 轮已收成"只许同轮之内搬"），
  否则活档 91803 那种 `currentSig="-1"` + 旗子为空的形状部署后照样赖在板上。撞关键词的任务不受这一刀影响，
  它走最后一道 `kwHit + QuestHasCredential`。
  第三十二轮（§32）把"命中关键词"这一道**降级成"绕过金币门槛"的标记**：撞名不再单独够格，还要
  `Ledger.QuestHasCredential` 答得出"客户端今天还答得出它"（池见过 / 日志收的 / 注册过 / 读到过金币 /
  客户端自己答过图 / **本轮任一角色被客户端答成已完成** `L.DoneByAnyCharThisRound`，命中任一即可）。
  最后这一条是本轮从他反弹里补的（96718 奈格塔尔虚空决战（英雄）：14 个号本轮交掉了，
  可它交完就掉出任务日志、`kwLogAdded` 被"还挂在日志里才续期"的规则撤掉 ⇒ 做完反而把凭据做没了）；
  它只认 `view.t ≥ L.RoundAt` 的 done 快照，**不读 `db.manual`**（玩家手点的补录不算客户端答复）。
  它的外沿是这条记录自己的到期门，不是轮次起点：不在池里的记录没人替它推 `roundAt`（`RollRound` 只由池换轮 /
  结束时间变化写），12.1.5 真存档把时钟推到 10-29 07:30 重放，96718 随 `expiresAt` 掉出矩阵而这条凭据那一刻仍答 true。
  **到期门只认"本轮之内读到的那条到期时刻"**（第三十四轮，唯一真源 `Ledger.EffectiveExpiry`）：同一个 questID 跨实例
  复用，换轮只推 `roundAt`、不清 `expiresAt`，而做完它的那个号身上客户端答不出新倒计时（`Api.QuestTimeLeft=nil`、
  `HaveQuestRewardData=false`）⇒ 到期时刻一直停在上一条实例，12.1.5 实测 89267 整行被吃掉。
  `exp < 本轮起点` 就是上一条实例留下的，本轮不作数，等接口自己写新的；矩阵、屏蔽右栏、悬停剩余时间、
  `NextRefreshAt` 唤醒定时器与 `/gql quest` 报告五处都问这一条真源，谁都不许再自拼 `now >= rec.expiresAt`。
  语义因此是"**这周做了才在板上看到**"，不是"关键词命中就永远占一行"。
  玩家口述的地图（`mapSrc=玩家指定`）**不算凭据**——它是"在哪办"的备注，
  不是"这条还真存在"的证据。
  一次点击就能改回来，没有"回退最近 20 步"。
- `Api.lua`：插件里唯一读 WoW 世界任务/奖励/完成状态接口的层（候选名单逐个 `pcall`，
  取不到就返回原因并记 `LastDegrade`，由 dump/probe 如实显示；子帧遍历把四种形态都摊平成
  一张列表——迭代器函数 / 带 `Next` 的对象 / 回一张表 / 回逐个返回值，见 `ChildFrames`）。
  不做判定、不写账本。
- `Probe.lua`：`/gql probe` 取证——把候选接口的实测返回值与形状摊成可复制文本，
  UI 只允许接在这里验证过的入口。不承载功能。
- `LogWindow.lua`：多行 EditBox 日志窗，承载 probe 报告与诊断日志，沿用 AHSnipe 的
  窗内 Ctrl+A/C 复制回传。帧惰性创建，加载期不 `CreateFrame`（否则离线单测加载即炸）。
- `Sync.lua`：编排与时序（何时抓池、事件去抖、钱差窗口、族与关键词补扫）。
  不直接读任何 WoW 接口（一律经 `GQL.Api`），算账的交给 `Ledger`。
- `Dump.lua`：`/gql dump` 与 `/gql quest` 的只读文本导出；本周汇总直接读
  `Ledger.MatrixColumns`，不再自己算第二遍。**"这一行为什么不在矩阵上"也只问判据**
  （`RowAdmitted` / `EffectiveExpiry` / `OccupiesRow`，分岔顺序照 `MatrixRows`），
  上一版那句写死的"没命中关键词、本轮没人交过，金币也没到 X"是猜话，12.1.5 实测和紧下面那行自相矛盾。
  不改数据。
- `Track.lua`：地图 pin 上 Shift+左键记进账本 / 撤销屏蔽（`pinPools` 快路径 + 帧树递归兜底），
  外加矩阵"添加任务"打开的两栏「关键词 · 屏蔽管理」窗口兜底——左栏是玩家自己的关键词，
  选中一个，右栏列它命中的任务（跟踪地图的世界任务池 ∪ 账本记录，**按名字去重**、零凭据与已过期的不列，
  最后一列是 questID——判据与矩阵同源，见 `Options.KeywordMatches`），
  **点一行"取消忽略" = 撤销那句"别再显示"**（不是"标记这条要上板"，用户 2026-10-27 定的口径），
  不许手输 ID（用户定的：记录类补录必须点击，ID 由接口枚举出来）。
  不是右键——右键=地图返回上一级、`Ctrl+左键`=定位标记，都被原生占用（用户实测）。
- `Matrix.lua`：任务×角色矩阵（把 `Ledger` 摊好的数据画成帧）+ 挂在
  `Api.Resolve("Minimap")` 上的小地图按钮（可拖动换角度，角度存 `minimapAngle`）。
  **没有行虚拟化**：每次重绘全量排版，文字/列头/热区各自按池复用，超出窗口的部分由
  `ScrollFrame` 裁剪；重绘在 0.25 秒窗口内合并（`Refresh` 排队、`RefreshNow` 同步画）。
  不判金币、不算轮次。**矩阵不提供屏蔽入口**（2026-10-27 玩家点名撤掉：他手滑右键误屏蔽了一行）——
  行热区那颗右键按钮连同 `RegisterForClicks`/`OnClick` 整块下线，右键在矩阵里什么都不发生；
  屏蔽与找回只在两栏「关键词 · 屏蔽管理」窗口（`Options.PanelToggleQuest` 那颗"忽略/取消忽略"）发生，
  旧"添加任务"弹框（`OpenAddDialog`/`RefreshAddList`/`Mx.listed`）整块下线，那颗按钮改开上面那扇窗口。
- `Options.lua`：两件事。① 设置面板 —— 只剩"跟踪地图"一段（关键词段、金币门槛段、
  "登录时抓一次世界任务池"那颗勾、大段说明文字、面板内"刷新"按钮 2026-10-27 全部撤下；
  入口挪走不等于功能废了，加/删关键词与补扫都在②里面，登录抓池则退回"默认开 + 改存档才能关"）。② 两栏「关键词 · 屏蔽管理」窗口 —— 命中集合由
  `Options.KeywordMatches` 现场算（账本 ∪ `Api.GetPool()`，纯子串、大小写不敏感），第三十二轮起它的过滤判据
  **与矩阵同一条真源**：凭据读 `Ledger.QuestHasCredential`、到期读 `Ledger.EffectiveExpiry`（第三十四轮：矩阵放行后
  悬停与这一栏都改问它，`now >= rec.expiresAt` 那句自拼判据下线）、同名只留证据最强的一条（打分口径同矩阵：
  池 > 读到过金币 > 客户端答过图 > 有剩余时间 > 小 ID；"有剩余时间"那一格打的也是本轮生效的那条到期时刻）；
  **两个例外**——玩家屏蔽过的行无条件留（那颗"取消忽略"是唯一的找回路），这一栏也不套矩阵的金币门槛
  （门槛判"哪条值得刷"，这一栏管屏蔽/找回）。最后一列从金额换成 **questID**
  （用户 2026-10-27："最好加上questId，不用加金额"；`nil ≠ 0 金币` 那条实测教训跟着归回矩阵的金额列与悬停）。
  按钮只调既有入口（`Track.*` / `Config.*` / `Sync.*`），自己不写任何数据。纯帧实现，
  不依赖暴雪 Settings API；"补扫跟踪地图"只是调 `Sync.HuntKeywordMaps`，自己不扫池。

`Ledger.lua` 独立出来是为了能进 `tests/run_gql_tests.py` 那套 lupa 离线单测
（`tests/run_tests.py` 是 AHSnipe 那套，跟本插件无关）：池 diff、签名变化、
轮次与 CD 归类、矩阵行列视图都能在游戏外验证。

## 10. 错误处理

- **API 缺失**：对应功能降级为"未知"（`?`），绝不让主流程报错，原因写日志窗口。
- **存档结构版本**：`db.schema` 与一次性升级函数 `Config.Migrate`（按档注册在
  `Config.MIGRATIONS`，当前 `Config.SCHEMA_VERSION = 4`）。只在 `Config.Init` 里跑一趟，
  不进每轮快照（那等于每次同步多一遍全账本扫描）。
- **升级失败**：**停在上一档、下次登录重试同一档**，并写一条日志
  （`数据升级失败 vN（下次登录重试）`）。逐档跑、一档失败就停——后面的档依赖前面的形状，
  跳档跑会把账本弄成半新半旧。绝不"备份原表再重建"：抹掉几个 CD 的金币记录比坏数据严重得多；
  坏数据由对应档的升级函数自己清（v2 = `Ledger.ResetStickyGoldOnce` 作废旧代码写错的
  "本轮读到过金币"，v3 = `Ledger.DropTurninsWithoutEvidence` 清掉查不到可信身份的交任务凭据，
  v4 = `Ledger.ClearManualAddsOnce` 作废老存档里"点一次永久有效"的手动添加标记 —— 只要往用户存档写过
  标记、这一版又加深了判据，档位就必须升，否则已吃过 v2 的存档（`stickyGoldReset=1` 那种）永远轮不到新档）。
- **判据本身报不出**时一律降级显示（`?` / 未判定计数），不猜。
- **改名/转服**：key 为 `角色名-服务器`。**这一条至今没实现**（代码里没有任何旧 key 提示与
  合并入口）：现在换名/转服就是账本里多出一列新角色，旧列照旧按"快照过期"标注，
  几周后由体积清理淘汰。要做的是"窗口提示是否把旧列迁移到新名字"，需点按钮确认、不自动合并。
- **钱差测量条件不满足**：记 `g = nil` 显示 `?`，不记可疑数字。
- **SavedVariables 膨胀**：`turnins` 每任务每 CD 上限 8 条；`observations` 每任务上限 4 条（按 `lastSeen` 淘汰最旧）；`quests` 中连续 3 个 CD 未出现的任务清出（保留其 turn-in 历史到下个 CD）。

## 11. 验收标准

1. 金币判定准确性：用用户游戏内回传的一批已知任务作基准，已知金币任务被自动标记，已知非金币任务不被标记。
2. 同步：角色登录一次后矩阵该列与游戏实际一致；未登录角色的列显示旧快照 + 时间。
3. 周统计：`cycleAnchor` 变化后本周统计归零，历史 CD 数字可回看。
4. 高频重刷：12 小时任务在同一 CD 内出现两轮时，第二轮重新计为待做，金币合计包含两轮。
5. 手动：地图头像点一次即改状态且不被下次登录覆盖；整列一键标完；撤销正确回退。
6. 池 diff：做完一个 12 小时任务使其消失，下次登录该行从"待做"变"本轮已结束"；同位置刷出新任务时自动入表并完成判定。
7. 模式差异：同一任务两种模式奖励不同 → tooltip 显示两条 observations，金币标记跟随当前池签名。
8. 离线单测：`Ledger.lua` 的池 diff、签名变化、轮次与周归类、矩阵行列视图在 `tests/run_gql_tests.py` 下全绿（`Ledger` 没有撤销栈，见 §9；验收 5 的"撤销正确回退"因此改成"移除后**永久**不再刷出来，只有玩家在'添加任务'里点回来才撤"）。

## 12. 实现顺序上的第一个非功能项

第 3 节的 API 未知意味着：**任何 UI 之前先做探测脚本**。第一个可交付物是 `/gql probe`，把候选接口的返回值与报错打进日志窗口，用户复制回传后据此确定唯一入口，再进 `Detect.lua` 正式实现。

两类退化，各自有明确表现，不允许静默假装成功：

- **"已完成"态查不到** → 该态退化为"事件记账 + 手动"两源，单元格显示 `?`（未知）而不是 `·`（待做），避免把"没查到"说成"没做"。
- **奖励列表查不到** → 金币判定失去预知能力：任务先以"未判定"入表，归到矩阵底部的"未判定"分组，等你做过一次由第 6 节 A 的实测金币自动转正为金币任务。此时第 11 节验收 1 不适用，改以验收 7 的模式差异为准。
