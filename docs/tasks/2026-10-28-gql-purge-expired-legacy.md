# GQL：清除老 expiresAt 遗留数据（v7 迁移）

日期：2026-10-28
状态：已完成（2026-10-28）

## 背景与问题

- 第 36 轮 T4a（94383f4）把到期门数据源从 `rec.expiresAt` 换成 `rec.roundEnd`（缺失退到周 CD 尾巴 = cycleAnchor + 604800）。
- 真档 310 条记录中仅 60 条有 roundEnd，218 条只有老字段 expiresAt，其中大量早已过期。
- 后果：离线重放同一存档，第 35 轮代码 19 行 → T4a 31 行 → T4b/T5 27 行，10 条死了数天的任务复活（全部顶着"下周重置才到期"的假倒计时），且周重置后锚点前滚会永久复活。
- 另有 2 条（94612 举钳欢庆、96718 奈格塔尔虚空决战（英雄））在新模型下行数异常，需核对字段后确认是否符合既有口径。

## 目标

新增 v7 迁移（Config.lua），在下次登录自动执行一次：

1. 删除：`rec.expiresAt` 已过期（< now）且非 regKey/kwLogAdded/ignored 的任务记录（用户拍板：早就到期的全部删除）。ignored 豁免与 Prune 同一道守卫：它是玩家"别再显示"的意图，删了三周后这条会自己刷回来。
2. 保留并转换：`rec.expiresAt` 未过期且无 roundEnd 的记录 → 把 `roundEnd` 盖章为该 expiresAt（一次性转成新模型真源，如本周周常、活倒计时）。
3. 注册类记录（regKey/kwLogAdded）一律保留：它们走 T5 设计的周 CD 尾巴，expiresAt 老值随字段退役被忽略。
4. SCHEMA_VERSION 6 → 7；真档 schema=5，下次登录依次跑 v6（烙编号）→ v7（清理）。
5. 时钟读取沿用 v6 的注入方式，测试可钉住 GQL_NOW。
6. 不动 turnins/views 等旁表（遵循现有 Prune 的清理口径，如有）。
