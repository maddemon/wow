# AHSnipe 拍卖行狙击插件 — 设计文档

> 状态：实现完成，Code Review 通过，待游戏内手工验证
> 日期：2026-10-13
> 目标：魔兽世界正式服（Retail 12.1）自用插件，定时扫描指定物品的一口价，发现低于门槛的低价（钓鱼甩货/诱饵）时弹窗提醒并支持一键打包购买。

## 1. 需求决策汇总

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 游戏版本 | 国服正式服 Retail 12.1，使用 `C_AuctionHouse` 新拍卖行 API |
| 2 | 购买范围 | 仅一口价（Buyout）listing，不参与竞拍/Bid |
| 3 | 比较口径 | 按**单价**（一口价 ÷ 数量）与门槛比较，用户设置的也是单价 |
| 4 | 默认门槛 | 主簇最低单价 × 65%（全局折扣可配置）；用户可按物品手动设置固定单价门槛覆盖 |
| 5 | 打包购买 | 单个"全部购买"按钮，按单价从低到高逐条买，失败跳过，完成后汇总成功/失败数与总花费 |
| 6 | 配置方式 | GUI 配置面板 `/ahsnipe`：物品列表、单价门槛、启用开关、删除；支持 Shift+点击背包物品 / 悬停添加 |
| 7 | 扫描条件 | 仅当打开拍卖行窗口时扫描，关闭即暂停；默认间隔 30 秒（可配置） |
| 8 | 命中通知 | 模态弹窗 + 音效；同一轮多个物品命中时只弹**门槛单价最高**的那个 |
| 9 | 金额保护 | 不做总额上限保护；弹窗明确展示单价 × 数量 = 总价，由用户自行确认 |
| 10 | 实现方案 | 方案 A：零依赖纯标准 Lua 插件，不使用 Ace3 等外部库 |

## 2. 背景说明

钓鱼甩货的诱饵价格有多个（如 17g89s、17g99s），但都显著低于真实价格簇（如 29g50s 起的大簇，挂单数量上万）。特征：

- 诱饵簇单价低、挂单数量极少（个位数）；
- 主簇（真实价格）挂单数量大、单价集中；
- 诱饵价与主簇最低价之比约 60%，是诱饵存活的"水位线"。

因此默认门槛取主簇最低单价 × 65%：既能抓到诱饵，又相对主簇留出约 35% 利润空间（扣手续费与价格波动后仍有赚头）。

## 3. 总体架构与文件结构

零依赖纯 Lua 插件，复制文件夹到 `Interface/AddOns` 即可使用：

```
AHSnipe/
├── AHSnipe.toc
├── Core.lua          -- 入口：SavedVariables 初始化、AUCTION_HOUSE_SHOW/CLOSED 事件驱动扫描开关、斜杠命令注册
├── Config.lua        -- 配置数据结构、物品增删查改、SavedVariables 读写
├── PriceCluster.lua  -- 价格簇分析与门槛计算（纯逻辑模块，无 WoW API 依赖，可独立测试）
├── Scanner.lua       -- AH 查询调度：串行遍历物品、收集聚合报价结果
├── BuyQueue.lua      -- 购买队列：按单价升序逐条购买、失败跳过、汇总
├── SnipeWindow.lua   -- 模态狙击弹窗 UI
└── ConfigPanel.lua   -- /ahsnipe 配置面板 UI
```

模块职责单一：UI 模块只负责渲染与交互回调，业务逻辑（门槛计算、队列调度）在独立模块中。

## 4. 扫描流程

- `AUCTION_HOUSE_SHOW` 启动周期计时器（`C_Timer`，默认 30 秒，可配置）；`AUCTION_HOUSE_CLOSED`（12.x 无 HIDE 事件）停止。
- 每轮扫描**串行**遍历已启用的监控物品：每轮只发起 1 个物品查询，收到结果或 10 秒超时后切换下一个，物品切换间隔约 1 秒，避免触发服务端查询节流。
- 查询路由：
  - 可堆叠物品（commodity，如矿石、鱼）→ `C_AuctionHouse.RefreshCommoditySearchResults`，结果经 `COMMODITY_SEARCH_RESULTS_ADDED` 事件分批返回后按单价归集；
  - 不可堆叠物品（装备等）→ `C_AuctionHouse.SendSearchQuery` 分支。
- 结果通过拍卖行事件异步返回后解析；解析时只保留**有有效一口价**的 listing，按单价归集。

## 5. 门槛计算（PriceCluster）

输入：当前物品全部一口价 listing 的单价与数量（单价升序）。

算法：

1. 相邻单价比值 ≥ 1.5 时切分价格簇（例：17.89 与 29.50 比值 1.65 → 分属两簇）。
2. 主簇 = 总挂单**数量**最多的簇（并列时取价格更高的簇）。
3. **默认门槛 = 主簇最低单价 × 折扣系数**（全局可配置，默认 0.65）。
4. 用户为某物品手动设置了固定单价门槛时，直接使用手动值，跳过自动计算。
5. 命中附加标注：命中 listing 的挂单数量 ≤ 10 且单价 ≤ 主簇最低单价 × 0.65 时，标记"疑似诱饵，注意秒删"。

边界场景：

- 挂单只有 1 条：整表即主簇，门槛 = 该单价 × 0.65。
- 挂单为空：跳过该物品，本轮不提示。
- 全部挂单单价相同（无断层）：单一簇即主簇。

## 6. 命中判定与弹窗

- 单价 ≤ 门槛的 listing 即为命中。
- 同一轮扫描多个物品命中时，只弹**门槛单价最高**的那个物品的弹窗，其余丢弃（下一轮自然重新扫到）。
- 弹窗为模态框（带音效提醒），内容：
  - 物品名、单价、数量、**总价 = 单价 × 数量**（原生金币格式化）；
  - "疑似诱饵"标注（如命中第 5 节附加条件）；
  - 【全部购买】【忽略】两个按钮。
- 弹窗未处理（未点按钮）期间不被后续命中覆盖；处理完后关闭。

## 7. 购买队列（BuyQueue）

- 点击【全部购买】：当前弹窗命中的 listing 按单价从低到高逐条调用购买 API。
- 每条间隔约 0.3 秒；
- 单条失败（已被买走、金币不足等）自动跳过继续下一条；
- 全部处理完后汇总展示："成功 N 条，失败 M 条，共花费 X 金 Y 银 Z 铜"（弹窗内 + 聊天框各一份）。

## 8. 配置面板（/ahsnipe）

- **物品列表**：每行显示物品名、单价门槛（手动值或"自动：计算值"）、启用开关、删除按钮。
- **添加物品**：
  - Shift+点击背包物品；
  - 鼠标悬停在 AH 列表/任意物品上后点击"添加悬停物品"按钮（避免手输物品ID）。
- **全局设置**：扫描间隔（默认 30 秒）、折扣系数（默认 0.65）。
- 配置持久化到 SavedVariables，跨角色共享。

## 9. 错误处理

- AH 查询 10 秒无响应 → 跳过该物品，本轮继续处理后续物品。
- 购买全程受玩家金币限制，金币不足时后续条目自动跳过并在汇总中提示。
- 加载时接口版本检测（`WOW_PROJECT_MAINLINE`），非正式服直接禁用并输出提示。

## 10. 测试策略

- **价格簇算法**：PriceCluster 为纯逻辑模块，游戏外用 Lua 脚本跑单测用例：
  - 正常场景（主簇 + 诱饵簇，验证门槛落在诱饵价与主簇低价之间）；
  - 单一价格簇；仅 1 条挂单；空挂单；
  - 诱饵多个价格（17.89/17.99）被正确归入同一低价簇；
  - 并列挂单数取更高价簇。
- **语法检查**：全部 Lua 文件过 luacheck。
- **游戏内手工验证清单**（实现完成后附验收记录）：
  - 添加/删除/启停物品，配置跨登录保留；
  - 打开/关闭 AH 窗口扫描启停；
  - 弹窗显示单价、数量、总价、诱饵标注；
  - 全部购买逐条执行、失败跳过、汇总正确；
  - 多物品同时命中只弹门槛最高者。

## 11. 验收标准

1. 打开拍卖行后，30 秒内可发现新上架的低于门槛诱饵单并弹模态窗。
2. 弹窗价格信息与 AH 界面实际挂单一致，点击全部购买后物品进入背包、金币扣减正确。
3. 关闭拍卖行窗口后不再发起任何 AH 查询。
4. 配置面板可完成物品增删与参数调整，重启游戏后配置保留。

## 12. 游戏内手工验证清单

插件安装：将 `AHSnipe` 文件夹复制到 `World of Warcraft/_retail_/Interface/AddOns/`，重启游戏或 `/reload`。

- [ ] 1. 输入 `/ahsnipe` 打开配置面板；Shift+点击背包物品、悬停 AH 物品后点"添加悬停物品"均可添加。
- [ ] 2. 删除物品、切换启用开关、重启游戏后配置保留。
- [ ] 3. 门槛输入框填 "6g50s" 或留空（自动），回车后显示正确。
- [ ] 4. 打开拍卖行窗口约 30 秒后聊天框有扫描启动迹象；关闭窗口后再开聊天框验证 `/ahsnipe scan` 提示"扫描未启用"。
- [ ] 5. 找一个钓鱼甩货物品（单价低于主簇 65%）验证：弹窗显示单价、数量、总价，与 AH 界面数字一致；疑似诱饵标注出现。
- [ ] 6. 点击"全部购买"：物品进入背包、金币扣减、聊天框/弹窗显示"成功 N 条，失败 M 条，共花费 X"。
- [ ] 7. 多个物品同时设置低价门槛并同轮命中：只弹门槛最高的那个。
- [ ] 8. 手动设置固定单价门槛后，命中仅按该门槛判断（不受自动计算影响）。
